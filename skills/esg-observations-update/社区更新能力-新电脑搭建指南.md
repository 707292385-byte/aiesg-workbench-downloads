# 社区更新能力（每日23:00更新资讯动态与研究洞察）迁移到新电脑指南

## 〇、架构提示（先看这个）

每日 23:00「更新社区」和每日 9:00「推送资讯」**读写同一个数据文件** community-public.json，
**两个任务必须放在同一台电脑上**，否则推送端读到的不是最新数据。
两台机器也绝不能同时开更新任务，避免互相覆盖。

本指南只覆盖「更新社区」能力；9:00 推送迁移见《ESG资讯推送-迁移到新电脑指南.md》。

## 一、新电脑环境准备（一次性）

1. **WorkBuddy 安装并登录同一账号**（Claw 通道可用）。
2. **克隆项目仓库**（GitHub）：
   ```bash
   git clone https://github.com/707292385-byte/consultant-os.git
   # 建议放到与原机相同风格的路径，如 ~/01 工作/AI项目/AIxESG平台
   # 记下实际路径，后面任务说明里的工作目录/数据文件路径都要替换
   ```
3. **拷贝技能**：把本机 `~/.workbuddy/skills/esg-observations-update/` 整个文件夹
   拷到新电脑同路径（`~/.workbuddy/skills/esg-observations-update/`），重启 WorkBuddy 生效。
4. **拷贝发布脚本**：本机项目里的 `tmp/20260925-standards-observations/`
   （publish_noproxy.py / verify.cjs / add_observations.py）随仓库一起同步；若 tmp 未入库则单独拷贝。
5. **GitHub 推送凭证**：发布走 git push 到 707292385-byte/aiesg-workbench-downloads，
   新电脑需配置 git 凭证（gh auth login 或 HTTPS PAT + credential helper）。
   注意发布脚本会读项目本地 git config 的 user.name / user.email，克隆后要配好。
6. **代理**：线上核验步骤会用 `-x http://127.0.0.1:6960` 访问 raw.githubusercontent.com，
   新电脑的本地代理端口若不同，需在执行时相应调整（或保证网络可直连 GitHub）。
7. **依赖**：python3（json/shutil 标准库即可）、node（跑 verify.cjs 渲染校验，WorkBuddy 自带）。

## 二、在新电脑 WorkBuddy 里重建定时任务

对话里说「建一个定时任务」，调度设为**每天 23:00（recurring）**，
任务说明按下面顺序操作：

1. 先让新电脑的小研执行：`查看本机技能列表，加载 esg-observations-update 技能`，确认技能可用；
2. 把本机任务的完整 prompt 粘贴过去（见第三节），并把其中所有路径替换为新电脑实际路径：
   - 工作目录：`<新路径>/AIxESG平台`
   - 数据文件：`<新路径>/AIxESG平台/knowledge-pages/assets/community-public.json`
   - 发布脚本：`<新路径>/AIxESG平台/tmp/20260925-standards-observations/publish_noproxy.py`
   - 敏感字段扫描路径等如涉及绝对路径一并替换
3. 建好后手动跑一次验证：「现在执行一次社区更新（不发布，只检索入库）」，检查：
   - 能正常检索、写入 JSON、三项校验通过；
   - 渲染验证能起本地服务（需要同意沙箱外执行）；
   - 发布与线上核验能推到 GitHub Pages。

## 三、任务说明全文获取方式

本机自动化「每日 23:00 更新 ESG 资讯动态与研究洞察并推送上线」的完整 prompt 较长（约4千字），
不用手抄：对新电脑小研说「按指南搭建社区更新任务」时，
可从本机导出——在本机对小研说「把 23:00 社区更新任务的 prompt 完整导出到文件」，
生成后把文件内容拷到新电脑使用。

## 四、切换与收尾

1. 新电脑连续 2 晚跑通后再切换；
2. 回本机对小研说「停用每日23:00社区更新任务」，只保留新电脑的；
3. 两台的 9:00 推送任务同样只保留一个；
4. 数据文件以仓库为准：切换后新电脑以 git pull 后的 community-public.json 为最新基线。

## 五、风险与注意

- 渲染验证步骤需要「沙箱外执行」授权，新电脑首次运行会弹授权，记得同意；
- 发布脚本带重试逻辑（git CONNECT 502 重试），网络抖动不用管；
- 若某栏目当日无新增，任务会按规则不推送，属正常现象，不是故障；
- 两台电脑的社区更新任务互为备份的话，改为「备机任务设为 PAUSED，随时可启用」的模式。
